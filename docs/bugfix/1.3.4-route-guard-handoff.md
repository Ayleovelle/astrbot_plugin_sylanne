# Embodiment-1.3.4 Bugfix 交接文档

## 修复概要

| # | 文件 | 问题 | 严重程度 |
|---|------|------|----------|
| 1 | `main.py` | `_register_web_apis` 直接引用 `wr.xxx_handler`，若 `webui_routes.py` 版本不一致（缺少 handler），插件加载时 AttributeError 崩溃 | 致命 |

## 影响范围

- 从旧版本（如 1.2.5）升级到 1.3.3 时，若 `webui_routes.py` 未完整更新（插件市场缓存/部分下载/.pyc 残留），插件无法加载
- 报错用户：@MengBad（issue #3 最新评论，2026-05-29）

## 复现条件

- `main.py` 为 1.3.3 版本（包含 `meltdown_nonce_handler` 路由注册）
- `webui_routes.py` 为旧版本（不含 `meltdown_nonce_handler` 方法）
- 插件初始化时 `wr.meltdown_nonce_handler` 触发 AttributeError

## 修复内容

### 路由注册改为 getattr 延迟解析

将 WebUI 路由从直接属性引用改为字符串名 + `getattr` 安全解析：

```python
# Before — 任何 handler 缺失都会崩溃
routes = [
    (f"/{P}/webui", wr.page_handler, ["GET"], "..."),
    (f"/{P}/api/meltdown_nonce", wr.meltdown_nonce_handler, ["GET"], "..."),
    ...
]
for path, handler, methods, desc in routes:
    context.register_web_api(path, handler, methods, desc)

# After — 缺失的 handler 跳过并打 warning
webui_routes = [
    (f"/{P}/webui", "page_handler", ["GET"]),
    (f"/{P}/api/meltdown_nonce", "meltdown_nonce_handler", ["GET"]),
    ...
]
for path, handler_name, methods in webui_routes:
    handler = getattr(wr, handler_name, None)
    if handler is None:
        logger.warning(
            "WebUI route %s skipped: handler '%s' not found"
            " — possible version mismatch in webui_routes.py",
            path, handler_name,
        )
        continue
    routes.append((path, handler, methods, f"Sylanne {handler_name}"))
```

## 效果

- 即使 `webui_routes.py` 版本落后，插件仍能带着部分功能正常启动
- 缺失的路由在日志中有明确 warning，方便用户/开发者定位问题
- 不影响正常情况下的功能完整性

## 根因分析

这不是代码逻辑错误，而是**分发健壮性**问题。当插件的多个 .py 文件版本不一致时（常见于插件市场缓存、部分更新、.pyc 残留），直接属性引用会导致整个插件崩溃。getattr 兜底是防御性编程，确保"部分可用"优于"完全不可用"。
