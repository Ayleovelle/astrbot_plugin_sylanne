# 1.4.5 Bugfix Handoff — `_background_tasks` set/list 类型混淆

## Issue

[#15](https://github.com/Ayleovelle/astrbot_plugin_sylanne/issues/15) — 用户 ltk415 报告 v1.4.5 与 bot 对话后出现 `'set' object has no attribute 'extend'` / `'append'` 错误。

## 根因

`_background_tasks` 在某些运行环境下变成 `set` 而非预期的 `list`，导致 `.extend()` 和 `.append()` 全部崩溃。所有懒初始化点仅做了 `hasattr` 检查，未验证类型。

根因未完全确定。可能来源：
- AstrBot `Star` 基类可能设置了 `_background_tasks` 为 `set`
- 序列化/反序列化过程中类型丢失
- 某处代码错误赋值 `p._background_tasks = set()` 或 `{task}`

## 修复策略

**全面防御式修复**：每个 `_background_tasks` 消费点（`.append` / `.extend`）前都加类型校验 + 重建。所有守卫点打 `logger.warning` 以便线上追踪根因。

类型不匹配时 **重建为 `[]`**（而非 `list()` 转换），理由：如果 `set` 中的元素是旧任务残留，转成 `list` 后 `.remove()` 可能漏删，重建最安全。

## 守卫代码模式

```python
# 入口守卫（懒初始化点）
if not hasattr(p, "_background_tasks") or not isinstance(p._background_tasks, list):
    if hasattr(p, "_background_tasks"):
        logger.warning(
            "Sylanne: _background_tasks type mismatch (expected list, got %s), rebuilding",
            type(p._background_tasks).__name__,
        )
    p._background_tasks = []

# 独立守卫（非入口 append 点）
if not isinstance(getattr(p, "_background_tasks", None), list):
    p._background_tasks = []
p._background_tasks.append(task)
```
