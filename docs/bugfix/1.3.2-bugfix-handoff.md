# Embodiment-1.3.2 Bugfix 交接文档

## 修复概要

| # | 文件 | 问题 | 严重程度 |
|---|------|------|----------|
| 1 | `sylanne_alpha/webui_server.py` | `global _last_diag_request` 声明在 `do_GET` 方法的 elif 分支内，位于同方法中变量使用之后，Python 编译阶段 SyntaxError | 致命 |
| 2 | `scripts/package_plugin.py` | `INCLUDE_DIRS` 缺少 `"UI"`，打包后无 `UI/index.html`，WebUI 显示 Dashboard unavailable | 致命 |
| 3 | `sylanne_alpha/webui_server.py` | `/favicon.ico` 未加入鉴权白名单，浏览器自动请求 401 | 低 |

## 影响范围

- Bug 1 导致 1.3.0 在所有 Python 版本上插件完全无法 import，等于发布即死
- Bug 2 即使修了 Bug 1，用户也只能看到空白 fallback 页面
- Bug 3 仅控制台报错，不影响功能

## 修复内容

### Bug 1: global 声明位置

```python
# Before (line 570, inside elif branch)
elif path == "/api/computation_logs":
    global _last_diag_request  # ← SyntaxError
    _last_diag_request = time.time()

# After (moved to method top)
def do_GET(self) -> None:
    global _last_diag_request  # ← 方法开头声明
    ...
    elif path == "/api/computation_logs":
        _last_diag_request = time.time()
```

### Bug 2: 打包缺少 UI 目录

```python
# scripts/package_plugin.py
INCLUDE_DIRS = {

```

### Bug 3: favicon 白名单

## 根因分析

1.3.0 开发时 `do_GET` 方法内的 `/api/computation_logs` 路由后加了 `global` 声明，但 `/api/state` 路由（同方法更早位置）已经读取了该变量。Python 不区分运行时分支——编译阶段扫描整个函数体，发现 global 在使用之后即报错。本地开发时如果用 aiohttp 路径（各路由是独立函数）则不会触发，只有走 stdlib fallback 路径才暴露。

打包问题则是 1.3.0 将前端从 `pages/` 迁移到 `UI/` 时未同步更新 `package_plugin.py`。
